# 首页添加进入空白画布

## 背景

当前首页的“添加”按钮直接触发导入流程，首页和空画布也都通过 `images.isEmpty()` 进入同一套空状态渲染。因此用户无法先进入一个完整的空白画布，再从画布顶部工具栏选择导入来源。

本次需求将首页的“添加”改为“创建空白画布”。空白画布复用现有主画布布局和顶部工具栏；用户通过顶部添加按钮选择载入图片或打开 PockRef 场景文件。

## 目标与非目标

### 目标

- 首页点击“添加”后进入现有画布布局，而不是直接打开系统 picker。
- 空白画布显示现有顶部工具栏，顶部添加按钮可正常使用。
- 顶部添加菜单中的图片入口和场景文件入口分离：
  - 图片入口只选择普通图片，并复用现有图片导入流程；
  - 文件入口只打开 PockRef `.pur` 场景文件，并复用现有场景加载流程。
- 空白画布取消 picker 后仍保持打开状态。
- 空白画布按系统返回键或点击顶部关闭按钮后回到首页，并丢弃空白场景。
- 空白场景不写入最近文件、不自动保存、不创建 `.pur` 文件。
- 图片成功载入后转为现有的普通未保存场景流程。
- `.pur` 成功打开后转为现有的已打开场景流程。
- 增加状态转换和入口分流测试。

### 非目标

- 不新增独立的 Activity、Navigation route 或新页面。
- 不改变主画布的绘制、缩放、平移、选择、背景色或手势行为。
- 不改变已有最近文件的排序、打开、删除和置顶规则。
- 不改变已有 `.pur` 文件读取格式兼容逻辑。
- 不在空画布中央增加额外的导入卡片或按钮。
- 不处理与本需求无关的工作区未提交改动。

## 状态模型

在 `PockRefUiState` 中增加独立的临时状态 `blankCanvasOpen`，用于区分以下三种状态：

| 状态 | `blankCanvasOpen` | 场景内容 | 展示内容 |
| --- | --- | --- | --- |
| 首页 | `false` | 无 | 首页卡片、最近文件和首页添加按钮 |
| 临时空白画布 | `true` | 无 | 完整画布布局和顶部工具栏 |
| 普通场景 | `false` | 有图片或标记 | 完整画布布局和场景工具栏 |

`blankCanvasOpen` 是一次性 UI/生命周期状态，不属于 `PockRefScene` 的持久化数据，不参与场景内容哈希，不写入 `AppPreferences`，也不创建最近文件记录。

新增 action 用于打开和关闭临时空白画布。打开 action 的 reducer 应至少清理上一层首页状态可能残留的临时交互状态，包括最近文件多选、最近文件选择、导入菜单和选择状态；画布背景和用户设置沿用当前 `PockRefUiState` 的已有值。

## UI 与数据流

### 首页添加

首页 `EmptyCanvasState` 中的添加按钮不再直接启动图片/混合 picker，而是 dispatch 创建空白画布 action。状态更新后，`PockRefApp` 的主内容分支根据 `blankCanvasOpen` 进入画布布局。

首页仍保留最近文件列表和现有首页辅助功能；这些内容只在 `blankCanvasOpen == false` 且没有场景内容时渲染。

### 空白画布渲染

画布分支的显示条件从“存在场景内容”扩展为“存在场景内容或 `blankCanvasOpen`”。空白画布使用现有 `CanvasPanel`，因此继续拥有：

- 画布背景和 viewport 状态；
- 顶部工具栏；
- 顶部添加菜单；
- 现有关闭按钮和系统返回处理；
- 画布的平移、缩放和其它既有手势。

空白画布不显示首页的 `EmptyCanvasState`、最近文件网格或首页日志导出入口。

### 顶部添加菜单

顶部添加按钮继续打开现有的来源菜单，但来源回调调整为明确的图片/场景边界：

- **图片来源**：相册、文件中的图片、剪贴板、拍照等现有图片入口继续调用 `ImportImages` 或专用图片导入 action。图片 picker 使用 `image/*` 或 Photo Picker 的图片过滤，不再把 `.pur` MIME 混入图片入口。
- **打开文件**：单独调用场景文件 picker，使用 PockRef 场景 MIME 和历史兼容 MIME；返回 URI 后先按显示文件名校验 `.pur` 扩展名，再调用 `LoadScene`。校验失败时通过现有错误通道提示用户，当前空白画布保持打开。

顶部来源菜单关闭后再启动 picker，避免菜单 scrim 或菜单状态拦截 picker 返回后的首次交互。picker 取消不 dispatch 场景关闭 action。

## 生命周期与返回行为

### 临时空白画布关闭

系统返回键和顶部关闭按钮共用关闭判定，但临时空白画布优先走一次性清理路径：

1. 关闭顶部来源菜单或其它瞬时 overlay（如当前已有的优先级规则要求）；
2. 如果 `blankCanvasOpen == true` 且场景仍无内容，清除 `blankCanvasOpen` 及相关临时选择/导入状态；
3. 回到首页，不弹未保存对话框，不更新最近文件；
4. 如果空白画布已经载入图片或标记内容，清除临时标记并转入现有未保存场景关闭逻辑，由现有规则决定是否显示保存提示。

点击顶部关闭按钮遵循同一规则，不能把临时空白画布写成一个空 `.pur` 文件。

### 导入或打开成功

- 图片导入成功后，现有 `importImages` 流程负责生成场景内容、命名未保存场景并更新 viewport；同时清除 `blankCanvasOpen`，让后续关闭行为使用普通未保存场景规则。
- `.pur` 加载成功后，现有 `loadScene` 流程负责设置 `currentSceneUri`、场景名、已打开文件状态和最近文件记录；同时清除 `blankCanvasOpen`。
- 导入失败、文件校验失败或场景加载失败时，保持 `blankCanvasOpen == true`，用户可以重新打开顶部添加菜单。

## ViewModel 与持久化边界

`blankCanvasOpen` 只存在于共享 `PockRefUiState`，由 `PureRefViewModel` reducer 管理。场景保存、自动保存、恢复会话和最近文件序列化逻辑不得读取或写入该字段。

创建空白画布时不设置 `currentSceneUri`，不设置 `isImportedPurFile`，不调用最近文件记录函数，也不触发自动保存。关闭空白画布时清理画布临时状态，但保留用户级设置，例如主题、背景颜色和手势开关。

需要检查所有判断“场景已打开”的位置：

- 画布渲染条件；
- `BackHandler` 的启用条件和优先级；
- 顶部工具栏、底部 FAB、minimap 等 chrome 的显示条件；
- 自动保存和异常恢复触发条件；
- 最近文件多选相关 UI。

这些判断应区分“需要显示画布”与“存在可持久化场景内容”，不能简单把 `blankCanvasOpen` 等同于 `hasSceneContent`。

## 错误处理与兼容性

- 图片 picker 取消、没有返回 URI 或图片解码失败时，沿用现有图片导入错误通道，空白画布不关闭。
- 场景 picker 取消时不产生错误，空白画布不关闭。
- 场景 URI 的显示名不是 `.pur` 时，不调用场景解析器，提示“请选择 `.pur` 场景文件”。
- 场景解析或读取失败时，沿用现有 `loadScene` 错误提示和临时文件清理逻辑，空白画布仍可继续操作。
- 历史 `.pur` 文件使用旧 MIME 或通用二进制 MIME 时继续可打开；文件名扩展名校验用于限制入口语义，不改变底层旧格式读取兼容。
- 已有正常场景的顶部添加行为、关闭行为和最近文件行为保持不变。

## 测试计划

### 状态与 reducer 测试

1. 首页 dispatch 创建空白画布后，`blankCanvasOpen == true`，图片、标记和最近文件列表不变。
2. 空白画布关闭后，`blankCanvasOpen == false`，场景仍为空，最近文件列表不变。
3. 空白画布关闭不产生未保存对话框，不触发保存或最近文件写入。
4. 空白画布载入图片成功后，临时状态被清除并进入普通未保存场景状态。
5. 空白画布打开 `.pur` 成功后，临时状态被清除并进入正常场景文件状态。

### 入口分流测试

1. 图片入口只向图片导入 action 提供 `image/*` URI。
2. `.pur` 入口接受 PockRef 场景 MIME和历史兼容 MIME，但拒绝非 `.pur` 文件名。
3. picker 取消不会改变空白画布状态。
4. 非法场景文件不会调用 `LoadScene`，并且空白画布保持打开。
