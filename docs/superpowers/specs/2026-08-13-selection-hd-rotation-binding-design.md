# 选中图片 HD 控件旋转绑定

## 目标

修复单张选中图片旋转时，右下角 `HD` 控件脱离图片的问题。`HD` 控件需要绑定到图片的局部右下角，并跟随图片的旋转角度一起旋转。

## 范围

- 只影响单选图片的 `HD` 控件布局和视觉变换。
- 保留现有 `SelectionHdControl` 的 Compose 点击、无障碍语义和状态样式。
- 不改变 HD 状态持久化、图片解码、撤销重做或旋转手势逻辑。
- 多选时不显示该控件，GIF 图片继续隐藏该控件。

## 方案

当前实现先计算旋转图片的轴对齐外接框，再把控件放在外接框右下角。该坐标不属于图片自身的变换坐标系，因此图片旋转后控件无法保持绑定。

改为以下布局流程：

1. 计算图片在屏幕上的中心、未旋转宽高和当前拖动偏移，使用与图片绘制相同的画布变换参数。
2. 在图片未旋转的局部矩形内计算控件中心。图片足够大时，中心位于右下角向内缩 `8dp` 的位置；空间不足时沿用现有策略，回退到图片中心。
3. 以图片中心为旋转 pivot，将局部控件中心按 `rotationDegrees` 投影到屏幕坐标。
4. 通过 `graphicsLayer.rotationZ` 旋转 `SelectionHdControl`，使控件外形和文字与图片保持相同角度。

图片的水平或垂直翻转会先作用于控件的图片局部坐标，因此控件位置会和图片的局部角点一起变换；控件自身不镜像，确保 `HD` 文字始终可读。这样位置计算与图片绘制的 `rotate { scale(flip) { ... } }` 顺序保持一致。

## 数据流与边界

- `PureRefApp.kt` 负责提供当前图片的屏幕中心、尺寸、旋转角度和临时拖动偏移。
- `SelectionHdControl.kt` 提供纯坐标计算函数和现有 Composable 控件。
- 当视口尺寸无效、没有符合条件的单选图片或图片是 GIF 时，不渲染控件。
- 控件位置随画布缩放、平移、图片移动和图片旋转实时重新计算。
- 控件大小保持现有的 `52dp x 44dp` 屏幕尺寸，不随画布缩放而改变。

## 测试

增加纯函数测试覆盖：

- 未旋转图片使用右下角内缩位置。
- 旋转 `90°` 和 `180°` 后，控件中心按图片中心正确旋转。
- 水平或垂直翻转后，控件位置按同一局部变换链正确投影，文字保持可读。
- 图片尺寸不足时回退到图片中心。
