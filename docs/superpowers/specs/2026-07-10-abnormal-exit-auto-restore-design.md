# 异常退出后自动恢复内部备份

## 目标

设备突然关机、应用闪退或进程被系统强制终止后，用户下次冷启动 PockRef 时，应用自动恢复最近一次有效内部自动备份，不弹出确认框。

## 恢复条件

仅当以下条件全部满足时执行恢复：

1. 本次是应用冷启动。
2. 启动时没有外部 `.pur` 文件打开请求。
3. 上一次运行留下了未正常结束的会话标记。
4. 内部自动备份目录中至少存在一个可以完整解析的备份。

外部文件启动优先级高于内部恢复。Activity 重建、配置变化和同一进程内的 `onNewIntent` 不触发异常恢复。

## 会话标记

- 应用冷启动完成初始化后写入“会话进行中”标记，并同步落盘。
- 用户通过应用内正常关闭、明确丢弃当前场景或正常退出流程结束会话时清除标记。
- 闪退、突然关机、强制停止和直接杀进程无法执行清理，因此标记会保留到下次启动。
- 不使用 `onPause`、`onStop` 或普通 Activity 销毁清理标记，因为后台切换和配置变化不代表正常结束工作会话。

## 恢复流程

1. 启动时先读取上一次会话是否异常结束。
2. 若存在外部打开请求，则正常打开外部文件并跳过恢复。
3. 否则按修改时间从新到旧枚举内部备份。
4. 逐个使用 `PurSceneCodec` 完整解析，首个成功解析的备份作为恢复源。
5. 将场景加载到共享 `PockRefUiState`，清空选择、手势和临时编辑状态。
6. 不把内部备份路径设置为正式 `currentSceneUri`，恢复内容保持未保存状态。
7. 显示一次 Snackbar：`已恢复上次异常退出前的内容`。
8. 若所有备份都损坏或不可读，记录错误并正常进入空画布，不阻塞启动。

## 备份语义

- 恢复的是最近一次成功完成的自动保存，不保证包含崩溃瞬间尚未到保存周期的修改。
- 当前内部备份按场景名称覆盖，因此同名场景只保留最近一份。
- 恢复不会删除备份；后续自动保存成功后可以继续覆盖它。
- 明确丢弃或正常关闭场景时，应使旧备份失去自动恢复资格，避免下次启动重新出现已丢弃内容。

## 错误与兼容

- 旧版备份继续由现有向后兼容 codec 读取。
- 损坏的最新备份不会阻止尝试更旧的备份。
- 恢复失败只写日志并通过现有错误通道报告，不导致启动崩溃。
- 恢复逻辑不得覆盖外部用户指定文件，也不得把内部私有路径加入最近文件列表。

## 验证标准

1. 异常会话标记存在且有有效备份：冷启动自动恢复。
2. 正常结束会话：下次启动不恢复。
3. 外部 `.pur` Intent 启动：打开外部文件，不恢复备份。
4. 最新备份损坏、次新备份有效：恢复次新备份。
5. 所有备份损坏：进入空画布且不崩溃。
6. 恢复后的场景仍显示未保存状态。
7. Activity 重建不会重复执行恢复。
8. 自动保存专项测试和 Debug APK 构建通过。
