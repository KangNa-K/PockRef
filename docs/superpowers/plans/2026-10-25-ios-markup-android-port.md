# iOS 标记模式移植 Android：功能对齐与双向可编辑

日期：2026-10-25
状态：实施中。基础编辑、共享对象往返、套索、多选变换和局部擦除已落地；不能宣布全面移植完成。保留现有界面改动，2026-10-25 续作在独立副本验证后按基线差异合回。

### 当前实施与方案差异

- 当前使用 AnnotationDocument schema 1 + 原生归档失效/内容覆盖扩展标志，尚未实现下文建议的 schema 2 revision/指纹机制。旧原生归档不能覆盖 Android 编辑；显式空文档不会复活已删除内容。
- Android 已有画笔、荧光笔、线、箭头、矩形、椭圆、文字、对象橡皮、局部墨迹擦除、套索和多选；选区支持移动、缩放/旋转按钮以及拖拽手柄。
- 会话历史联合保存笔画/文字；完成合成一次场景撤销，取消恢复基线；自动保存不把可取消草稿覆盖已提交文档。
- 已验证 Swift/Android 实际 PUR 往返、legacy 标记文件、局部擦除后双端重开、稳定 ID、损坏元数据拒绝导入。
- 当前为矢量折线渲染/解析擦除，并未接入 AndroidX Ink；不具备与 PencilKit 等价的压感、倾斜和笔刷纹理。笔输入期间忽略额外手指导航，不等于已通过真机手掌防误触验收。
- PaperKit 26 全对象转换仍受公开 API 能力限制；未完整迁移的原生内容保持保护，不以预览代替可编辑对象。
- 更多形状、填充、完整锁定 UI、可配置 S Pen 临时工具、字体/文本框精确对齐、锁屏/进程死亡/写入失败/性能与物理设备验收仍待完成。
- 最新实测与独立目录/合并记录见 `docs/ios-markup-port-validation-2026-10-25.md`。

## 1. 目标和非目标

- Android 原生实现当前 iOS 标记模式的工具、对象编辑、撤销、保存和重开体验。
- 必须验证 iOS -> Android 编辑 -> iOS 再编辑，以及 Android -> iOS 编辑 -> Android 再编辑。
- 已有 iOS 文件属于迁移范围；允许先在具备转换能力的 Apple 设备上转换，再导入 Android，不预设 Android 能直接解析所有原生归档。
- 标记必须保留对象语义：文字仍是文字，形状仍是形状，笔画可选择、变换和擦除。预览图片只能兜底显示，不能视为完成可编辑迁移。
- 保留参考图片、分组、裁切、原图导出和 S Pen 在非标记模式中的既有行为。
- 本方案不包含云同步、多人协作、应用发布、签名版本升级或整个画布重写。
- 功能与数据语义对齐不等于不同系统笔刷纹理、字体栅格化逐像素一致；外观差异需单列验收，不隐瞒降级。

## 2. 当前代码基线

### Android

- `app/src/main/java/com/pockref/app/model/Models.kt`：工具只有 PEN/TEXT；笔画保存点、颜色、线宽；文本独立保存。
- `app/src/main/java/com/pockref/app/ui/PureRefViewModel.kt`：已有标记会话、取消恢复、独立撤销/重做。
- `app/src/main/java/com/pockref/app/ui/PureRefApp.kt`：已有绘制、文本界面和双指导航，不重写整个文件。
- `app/src/main/java/com/pockref/app/ui/MarkupHistory.kt`：已有笔画与文本联合快照，可借用事务语义。
- `app/src/main/java/com/pockref/app/data/PurFileParser.kt`：V2 drawings 当前进入图像读取路径；需要增加共用对象恢复及兼容图层去重，不能以此路径证明可编辑往返。
- `app/src/main/java/com/pockref/app/data/PurV2SceneWriter.kt`、`PurSceneCodec.kt`：已有 V2 metadata 和 legacy 扩展；扩展现有文件，不另起不兼容的保存通道。
- `app/src/main/java/com/pockref/app/data/AutoSaveManager.kt`、`SceneFileWriter.kt`：保留先编码再写入的安全路径，同时检查新字段是否进入内容变化检测与恢复链路。
- `app/src/main/java/com/pockref/app/MainActivity.kt`：S Pen 侧键直接分发图片框选动作，标记模式必须单独路由。
- 当前工具链为 AGP 8.5.2、Kotlin 1.9.24、Compose BOM 2024.06.00、compileSdk 34、minSdk 24；新增依赖前先验证，不顺便大范围升级。

### iOS

iOS 仓库根目录：`../ios/PockRef`，不是外层 `../ios`。

- `PockRef/Screens/MarkupSheet.swift`：系统 26+ PaperKit 路径；保存归档时保留 priorDocument，不保证新对象已同步到共用文档。
- `PockRef/Screens/PencilKitMarkupSheet.swift`：旧系统 PencilKit + 结构化对象，会话历史同时覆盖两层。
- `PockRef/Models/AnnotationDocument.swift`：schemaVersion 1；pen/highlighter/line/arrow/rectangle/ellipse/text，不足以表达所有新版形状和笔刷信息。
- `PockRef/Markup/PencilKitAnnotationAdapter.swift`：现有转换主要输出点与统一线宽；重建时使用固定 pressure/azimuth/altitude，不能宣称保留完整原笔迹动态。
- `PockRef/Canvas/MarkupCompatibilityViews.swift`：子元素访问现有代码受 compiler >= 6.4 和系统 27 条件限制，不能把接口直接用于 26。
- `PockRef/Pur/PurBinaryFormat.swift`、`PurSceneCodec.swift`、`PurFileParser.swift`：已有 annotationDocument、markupLayer、paperKitMarkup 三类数据；需要解决版本与权威来源，而非简单再加一个 JSON。

工作区已有画布 chrome、模型和测试等未提交改动；实现时必须保留，不重置、不覆盖、不自动提交这些改动。iOS 当前读取时工作区干净。

## 3. 最先验证的两个关卡

### G1：现有 iOS 文件能否恢复完整对象

建立不含用户隐私内容的最小测试文件，分别来自 PencilKit、PaperKit 26 和能够访问子元素的较新系统。逐项测试原生归档读取、元素枚举、坐标、样式、文本与遮罩提取。

- 共用 v1 对象：迁移到新结构；不存在的压感等历史信息保持缺失，不伪造。
- 只有 PKDrawing 的文件：在 Apple 侧解码，导出完整笔画采样、变换与擦除结果；保留原始归档。
- 只有 PaperKit 归档的旧文件：优先在具备公开子元素访问能力的 Apple 系统中打开并转换，再生成兼容文件。
- 不能完整提取的对象：保留原始归档、必要的预览和明确的限制报告；不得静默丢弃或标成已完成迁移。
- 如果要求不升级的系统 26 设备直接输出所有对象，先给出实际原型结论；若公开 API 不足，提交决策，不通过私有 API 或逆向归档绕过。

关卡通过条件：确认每一种目标对象的迁移能力、需要的最低系统和残余限制。任何核心对象仍无法转换，整体可编辑互通仍未完成。

### G2：Android 笔迹引擎

首选验证 AndroidX Ink 稳定版，Compose 负责工具栏和编辑控件，独立引擎负责实时手绘。2026-10-25 核验官方发布页：稳定版 1.0.0，最新 Alpha 为 1.1.0-alpha10（2026-10-21）。Alpha 的局部擦除不是稳定版默认能力，不能直接复制网站示例依赖。

原型检查：与当前 Gradle/Kotlin/Compose 的兼容性、实际最低系统、S Pen 压感、防误触、双指导航、笔画完成交接、擦除结果存储及离屏导出。不得为原型静默提高 minSdk。

局部擦除必须覆盖重开后的几何与外观；只擦掉屏幕临时图层不算完成。稳定版本无法满足时，对比独立矢量擦除方案与实验依赖风险后再决定。G1/G2 通过前不承诺完整排期，也不锁定需要大范围升级的依赖方案。

## 4. 共用数据契约：建议 AnnotationDocument v2

共用文档是已迁移对象的权威数据；原生归档是可校验的缓存或历史备份，不允许过期归档覆盖跨端编辑。

| 层次 | 必须定义的内容 |
| --- | --- |
| 文档 | schemaVersion、文档 ID、revision、坐标空间、对象有序列表、所需能力 |
| 通用对象 | 稳定 ID、kind、顺序、变换、可见性、锁定/允许操作、扩展字段 |
| 笔画 | 点、时间、可用时的压感/倾斜、宽度或轮廓、笔刷标识、透明度、擦除后几何/遮罩 |
| 形状 | 参数化几何、描边、填充、透明度、线端标记；区分线条箭头与实体箭头形状 |
| 文本 | Unicode 原文、文本框、字号、颜色、段落及必要富文本属性、字体请求与回退信息 |
| 归档 | 平台、归档格式、对应文档 revision/指纹、原始字节、是否完整覆盖当前对象 |
| 兼容显示 | 来源对象 ID、对应 revision、图层用途，避免预览和真实对象双重渲染 |

具体 JSON 编码以双端 golden fixtures 固定；尤其不能假定 Swift CGPoint/CGRect 的 Codable 表示等同于手写的 Android 对象结构。旋转单位、颜色范围、alpha 合成、文本坐标、画布原点与图片局部坐标都要明确。

- 主坐标使用场景世界坐标；对象可带局部变换，屏幕 zoom/pan 只影响显示。需要保留图片附着关系的旧标记记录其父对象，不未经确认改成全局标记。
- 对象 ID 不随拖动、颜色修改或重编码变化。
- 部分擦除通过可序列化几何/遮罩表达，不能使用背景色涂抹假装擦除。
- 删除全部对象是合法的显式空文档，不得回退恢复旧归档；数据不存在、解析失败和内容为空必须区分。
- 未知字段和未知对象尽量无损透传；无法安全往返时进入兼容只读/另存路径，不在保存时过滤掉。
- 对象可编辑性与外观保真分别记录。Apple 专有笔刷、不可用字体等不承诺无损重现；保留原始数据并显示差异。
- 增加大小、元素数量、坐标有限性和嵌入数据解码上限，避免损坏文件造成崩溃或异常内存分配。

### 防止回到 iOS 后新修改消失

1. 读取文件，先解析并验证共用文档 revision。
2. 仅当原生归档标注的源 revision/指纹匹配当前文档时，才允许直接使用。
3. Android 修改后递增 revision；原 iOS 归档可以保留为备份，但失效。
4. iOS 从最新共用对象重建当前编辑视图，不再无条件优先打开旧 paperKitMarkup。
5. iOS 完成编辑时同时更新共用文档及归档绑定，统一提交；任一步失败不覆盖最后成功的文件。
6. 不混合展示同一对象的 native、shared、preview 三份副本；仅隐藏有明确对应关系的兼容层，不能误删用户图片。

新格式面向更新后的两端应用保证互通；不能承诺未更新的旧应用理解新 schema。旧版本覆盖新文件的风险必须在兼容说明和导出界面明确提示。

## 5. Android 实现边界

建议在独立 markup 包内新增 Document/Session/InputRouter/Renderer/Codec/Toolbar，ViewModel 和 PureRefApp 只接入必要状态与动作。以上为拟定职责，不要求建立过度抽象的类层次。

- Session：独立 workingDocument，取消恢复原文档，完成后形成一个场景级历史项；内部每笔、每次拖动、每次文本编辑为一个撤销事务。
- 输入：笔绘制，双指导航；保留手指绘制选项。进入导航时明确处理未完成笔画，不让旧回调污染下一操作。
- S Pen：非标记模式保持图片框选；标记模式不透传框选，可配置临时橡皮/套索，默认绑定需按原型与用户习惯确认。
- 手绘：进行中的笔画在局部渲染层更新，避免每个采样点重建整个场景 StateFlow；完成后再提交文档。
- 对象编辑：独立命中测试、套索与变换手柄，锁定对象不得被间接擦除或选中修改。
- 文本：处理中文输入法 composing、软键盘、字体替换、多行换行、宽度调整和连续编辑事务，不能在每次键入时推全局历史。
- UI：沿用当前 Material/Dimens 和已有 chrome 改动，工具栏不遮挡菜单、键盘和选中对象；小屏/横屏/分屏分别验收。
- 保存：工作草稿恢复与已提交文档分离；自动保存不得把稍后会取消的草稿写回源文件。
- 检测：dirty hash、缩略图、列表预览、全画布导出都包含新模型；选中原图导出继续保留原文件语义。

## 6. 分阶段交付

阶段 1/2 的基础链路与阶段 3 的部分交互已实施；阶段 0 能力关卡及阶段 4 完整验收仍有缺口。下表是目标退出条件，不代表已全部满足。

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| 0 能力关卡 | G1 转换样本、G2 手写原型、工具功能对照表 | 明确旧 PaperKit 的可转换范围和依赖条件，不以预览替代成功 |
| 1 数据闭环 | 双端 v2 编解码、迁移、版本来源判定、文件写入保护 | 双向重开保持对象 ID、内容和顺序，未知数据不丢失 |
| 2 基础编辑 | 画笔、荧光笔、线、箭头、矩形/椭圆、文本、对象橡皮、统一历史 | 每类对象创建、编辑、撤销、保存、重开均通过 |
| 3 完整交互 | 套索、多选变换、局部擦除、更多形状、填充/样式、S Pen 与键盘适配 | 与当前 iOS 功能清单逐项对照，无核心功能缺口 |
| 4 迁移验收 | 旧文件转换流程、实际双端往返、性能、锁屏/后台/保存故障测试 | 核心旧文件完成可编辑迁移，安全与真机验收通过 |

先完成一条可运行的纵向链路，再扩展所有工具：iOS 的一笔 + 一个矩形 + 一段文本 -> Android 分别修改 -> 保存 -> iOS 修改仍在且仍可编辑 -> 再回 Android。该链路不通过，不以工具栏按钮数量判断进度。

## 7. 测试与完成标准

### 自动化

- Swift/Kotlin 共用同一批固定 JSON 与 PUR fixtures，比较语义、稳定 ID、对象顺序和原始归档字节；不依赖对象字段排列相同。
- 测试 v1/v2、未知对象、缺失字段、显式空文档、损坏文件与不支持版本。
- 进行不少于 10 次双向编解码循环，检测坐标/字号漂移、重复图层、删除复活、旧归档覆盖。数值容差需在第 0 阶段通过原型确定。
- 几何测试覆盖旋转/缩放后命中、反向拖动、画布负坐标、图片附着转换、擦除跨线段、锁定对象。
- 历史测试覆盖笔画 -> 形状 -> 文本混合操作、快速 undo/redo、完成回调延迟、取消、空操作、多指打断。借鉴已有 iOS 历史边界回归，而不是简单复制系统回调机制。
- 文件测试覆盖 legacy/V2、自动备份、源文件写入失败、编码失败、重开恢复、缩略图和 PNG 导出；现有场景/分组测试必须保留通过。

### 真机与实际文件

- Galaxy Tab + S Pen：压感、手掌误触、悬停、侧键、笔与手指切换、连续绘制和局部擦除。
- iPad：分别验证 PencilKit 和实际可用的 PaperKit 系统路径；不能用较新系统的成功替代旧系统验收。
- 横竖屏、分屏、键盘遮挡、长中文文本、锁屏、切后台、低内存/进程重建、异常退出后的草稿恢复。
- 使用同一组文件完成真实的双端打开/修改/保存往返，并对比图片、分组、标记、字体与透明度。
- 性能记录输入延迟、帧时间、内存和保存耗时，注明设备、系统、对象数量与测试方式；编译通过不代表书写体验合格。

完成必须同时满足：目标功能清单通过、确认范围内旧文件可编辑迁移、双向真实文件验证通过、无静默数据丢失、真机验收有记录。不支持对象与缺失测试明确标为未完成，不能只因实现了兜底预览而宣布全面移植完成。
