01 · PROBLEM

现状 · 为什么 portrait 下变成细条

Panel 尺寸公式（HEAD 现状）

PockRef 现有 CanvasMinimap 按 scene 的 AABB 长宽比算 panel 尺寸：

scene aspectwDphDpslider 可拖宽度
wide (aspect > 1) 200dp (long) 200 / aspect ~190dp ✓ OK
square (aspect = 1) 200dp 200dp ~190dp ✓ OK
portrait (aspect < 1) ⬅ 你的截图 200 × aspect ≈ 60-100dp 200dp ~30-80dp ✗ 不可用

你的截图里 scene 是 1080×1920 portrait 拼图 → aspect ≈ 0.56 → wDp = 200 × 0.56 ≈ 112dp，slider fillMaxWidth() 减去 panel padding（左右各 12dp）只剩 ~88dp 实际拖动空间——thumb 直径 20dp，几乎没有可拖范围。

图示：portrait scene 下 panel 被压窄，slider 实际可拖宽度只剩 30-80dp。宽 1.0x → 5.0x 共 9 档，每档只 3-9dp，拇指无法精确定位

02 · PLAN A

方案 A · Procreate 横向大 slider 推荐

形态

长按后整个 minimap 区域原地变形成横向 slider——宽度扩展到固定 240dp，高度压到 80dp，不依赖 scene aspect。形态转换 250ms emphasized。

优点

  • 240dp 固定宽度，portrait / landscape / square 一致体验
  • 9 档刻度每档 ~21dp，拇指 20dp 直径能精准落点
  • M3 Slider + TooltipBox（已有）直接用，无新组件
  • 跟现有 minimap 锚点兼容——minimap 中心点 = slider 中心点，形态转换 250ms 后锚点不变
  • 加 fit 按钮可一键 100%

缺点

  • 固定 240dp 宽 → wide scene 下 比 minimap 宽（minimap 短边最大 200dp）
  • 需要为形态转换设计宽→宽的尺寸过渡（不能用 SizeTransform 一刀切）
  • 80dp 高度在 minimap 模式是"瘦长形"，需要 morph 时高度也变化

M3 符合度

组件M3 Slider + TooltipBox + FilledTonalButton (fit)
曲线emphasized 250ms (展开) / standard 150ms (回弹)
色板colorScheme.primary 进度 / surfaceContainerHighest 轨道 / primaryContainer 容器
触摸48dp minimum (Slider 默认可达)

A 还有 2 个变体 · 横 vs 竖

你问"可以改成大竖条吗"——完全可以。M3 Slider 在 Compose 里是 orientation 参数（默认 Orientation.Horizontal，可设 Vertical）。下面是横竖对比，你挑一个：

A-横 · 240 × 80 (原方案)

  • 桌面 / 平板 M3 Slider 标准方向
  • 水平拖动距离最长 (240dp)
  • 底部留更多垂直空间给其它 chrome
  • 占用水平空间 240dp, portrait scene 中间位置可能跟图片重叠
  • 跟 minimap 方形形态"横向拉长", 形态不延续

A-竖 · 80 × 240 (你的提议)

  • 跟 minimap 方形形态延续 (方形→竖长方形, 视觉过渡自然)
  • 垂直拖动 = 调节 zoom 的"自然肌肉记忆" (音量条/亮度条)
  • portrait scene 里只占 80dp 水平, 跟图片边距友好
  • 底部 240dp 长 → thumb 在中间位置时也远离 minimap 边界
  • 240dp 高 → minimap 上下空间被吃掉
  • 下方有 selection status pill 时可能撞
  • 横屏 landscape 下, 240dp 竖条太"瘦长", 视觉突兀
03 · PLAN B

方案 B · Lightroom 圆形 zoom dial

形态

长按后变成 140dp 直径的圆形 dial——周围是环形进度条（指示当前 zoom），中心是数值大字号。手指绕中心点旋转调节 zoom：每 30° ≈ 0.5x。

优点

  • 视觉冲击强，"精密仪器"质感
  • 节省水平空间（140dp 圆 比 240dp 横条短）
  • 中心数值字号大，远距离可读（尤其平板距离）
  • 旋转手势在 S Pen 上非常跟手（240Hz 角度采样）

缺点

  • 不是 M3 标准组件——需要自绘 Canvas，开发量最大
  • a11y 复杂：旋转手势没有标准 TalkBack，需要自定义 progressBarRangeInfo
  • 键盘操作难做（没有"方向键 ↻ 旋转"的语义）
  • portrait 下 dial 仍要 140dp 高，占垂直空间
  • 用户需要学习"绕中心旋转"——非主流

M3 符合度

组件自绘 Canvas (arc) + Box (center number)
曲线emphasized 250ms (展开) / standard 150ms (回弹) + spring 越界
色板colorScheme.primary 弧 / outline 轨道 / onSurface 中心数字
触摸旋转检测 32dp 最小半径
符合度★★★ 3/5 — 自定义组件, 需手画 M3 颜色规范
04 · PLAN C

方案 C · iOS Camera 气泡 + 细 slider

形态

长按后 气泡浮出显示当前 zoom level（"2.5×"），气泡下方是细长 slider（200dp × 56dp）。气泡是 M3 TooltipBox 的升级版——有箭头指向 slider thumb。

优点

  • 跟当前实现最接近——只需微调 TooltipBox 样式（加箭头 + 放大字号）
  • 气泡跟随 thumb，视觉关联强（iOS Camera / Google Photos 用户习惯）
  • 开发量最小（跟现状差距 < 50 行）

缺点

  • slider 仍受 panel 宽限制——portrait 下 200dp 也可能不够
  • 气泡 + slider 高度 96dp，比方案 A 更高
  • 形态转换时气泡需要 fade-in / fade-out（多一层动画）
  • 没有 fit 按钮等扩展空间

M3 符合度

组件M3 TooltipBox (升级) + M3 Slider (缩小)
曲线emphasized 250ms (展开) / standard 150ms (回弹) — 气泡 fade 同步
色板colorScheme.inverseSurface 气泡 / primary slider 进度
触摸48dp minimum (Slider 默认可达)
符合度★★★★ 4/5 — TooltipBox 加箭头, 几乎全 M3
05 · PLAN D

方案 D · M3 Bottom Sheet 抽屉

形态

长按后从 minimap 位置 向上滑出 ModalBottomSheet，里面是 slider（占满宽）+ 5 个 preset 按钮（25% / 50% / 100% / 200% / 400%）。功能最全。

优点

  • slider 占满宽（460dp 实际拖动空间），永远直观
  • preset 按钮一键跳 0.25x/0.5x/1x/2x/4x，不用拖动就能精确到常用值
  • 功能最全——可以加 fit / 1:1 / 实际尺寸 / 自定义预设
  • M3 ModalBottomSheet 是标准组件，跟系统的 share sheet / quick settings 同款体验

缺点

  • scrim 覆盖场景 56% 高度，看不到当前 zoom 后的内容预览（除非用户先拖再 dismiss）
  • 占用 140dp 屏幕高度，视野被压
  • 长按 → sheet 出现 → 拖动 slider → 关闭的链路长，3 步操作，不如直接拖动 slider 快
  • scrim 体感"重"，不适合频繁调节 zoom 的场景
  • 跟现有 minimap 锚点关系弱——sheet 是独立的 modal

M3 符合度

组件M3 ModalBottomSheet + M3 Slider + FilledTonalButton (presets)
曲线emphasized 250ms (sheet 展开) / standard 150ms (dismiss) — M3 standard sheet 行为
色板colorScheme.surface sheet / scrim 用 onSurface @ 32% alpha
触摸48dp minimum (Slider + 按钮)
符合度★★★★★ 5/5 — 全 M3 标准组件

07 · PICK

推荐 + 选哪个

我的建议

方案 A · Procreate 横向大 slider

理由：

  1. 问题根因是 portrait 下 panel 被压窄——方案 A 切断"用 panel 宽度当 slider 宽度"的耦合，slider 宽度 = 固定 240dp，跟 scene aspect 无关
  2. 240dp × 80dp 是 3:1 横比，大拇指和 S Pen 都有充足命中空间（M3 48dp minimum + 实际 21dp/档）
  3. 实现量 180 行，跟当前 M3 重做方案同量级，不需要废弃之前 Slider 重写的代码
  4. 形态转换从 60-112dp 宽（minimap 模式）变到 240dp 宽（slider 模式），用 AnimatedContent + SizeTransform 自带宽度过渡，不破坏锚点
  5. 加 fit 按钮（方案 A 草图里右侧那个）一键回 1.0x，快速回 100% 比拖 slider 9 档快 5x

方案 B 适合谁

如果你想要"摄影 App 调焦"那种仪式感，S Pen 用户里特别追求视觉冲击的可以选。代价是 350 行自绘代码 + a11y 难做。

方案 C 适合谁

如果你只想"在现状上加箭头气泡"，追求最小改动。代价是 portrait 下的窄 panel 问题没解决——只是把数字放大了一点。

方案 D 适合谁

如果你想要 Procreate 那种"长按 → 工具抽屉 → 多按钮 + slider"的全功能。代价是 scrim 覆盖主画布 + 3 步操作长。

关于"锚点不变"：所有方案都保持 minimap 中心点 = slider 中心点。如果你想要 slider 出现在其他位置（比如底部工具栏），那是另一种范式——告诉我你想要什么样的位置。
